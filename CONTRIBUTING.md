# Contributing to Tuki Tales

Thanks for your interest in Tuki Tales! This project is currently in its
early setup phase, so contribution guidelines are intentionally minimal.

## Before You Contribute

1. **Open an issue first** — discuss the change you'd like to make before
   writing code. This avoids wasted effort on directions that may not align
   with the project's roadmap.
2. **Keep PRs small and focused** — one feature or fix per pull request.

## How to Contribute

1. Fork the repository
2. Create a feature branch from `main`:
   ```bash
   git checkout -b feat/your-feature-name
   ```
3. Make your changes with clear, conventional commit messages
   (e.g. `feat: add player movement`, `fix: correct scene load order`)
4. Push to your fork and open a Pull Request against `main`
5. Fill in the PR template and link the related issue

## Code Style

- Run formatters / linters before committing
- Prefer clarity over cleverness
- Add comments only when the "why" isn't obvious from the code

## Reporting Bugs

Open an issue with:
- Steps to reproduce
- Expected vs. actual behavior
- Environment (OS, runtime versions, etc.)
- Logs or screenshots if available

## Code of Conduct

Be respectful. Be constructive. We're all here to build something we're
proud of.
